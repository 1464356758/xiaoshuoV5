# 每章约6000汉字与前五章投稿验收

适用于本版新建作品。作者要求以后统一约6000汉字一章：首章、第二章、第三章及后续章均使用同一区间，目标6000，允许5500—6500，不再启用前三章4500字上限。保留约90万字目标，默认150章；不能因旧的100章总量公式在后期强迫章节回到9000字。旧书配置与已冻结正文不在本次修改范围。

## 开写前先把五章作为一个短期故事设计

先完成平台研究、作者选题、设定和长期路线，再获得开写授权。首章任务书的opening_five_plan写清目标读者、差异卖点、读者承诺、持续冲突，以及五章各自的目标、主动选择、可见结果、代价或他人反应和下一问。计划不是已发生事实，实际正文偏离时据因果调整后续，不篡改冻结章。

至少实际精读两部适配参考作品的开篇，每部从首个阅读单元起不少于一万汉字，建立arc或book层次的拆书记录；同书两个版本只算一部。导出摘要携带source_scope的范围、程序实测汉字数和reviewer_declared阅读声明，区分有据的模型阅读声明与自动验证。网页阅读单元不冒称已经核实的章节。

比较有效开篇怎样吸引、怎样让主角行动、怎样兑现第一项卖点、怎样把结果变成下一冲突。观察、适用前提、失败条件和本书原创差异必须具体。原有少量scene教材可以继续辅助局部写法，但不能充作完成了两部开篇的精读。教材不足时先读原文、补记录、提交参考库后再导出。

首章仍比较两种300—800汉字原创开场，再采用其中方向完成整章。这些试写草稿不作为正式章节登记。

## 前五章各自应带来什么

|章次|主要验收问题|常见失败|
|---|---|---|
|第一章|读者为何关心这个人？眼前麻烦逼他做了什么？卖点是否在前3000汉字产生可见结果？|堆背景、讲系统、结尾才遇事；章长达到6000却只有准备|
|第二章|首章结果怎样引出代价、关系变化或他人回应？主角是否继续做选择？|重新介绍前情；人物被安排着走；只是把首章结果解释一遍|
|第三章|首个短期承诺有没有实际兑现？优势的能力与限制是否在行动中被看见？|只抬高期待、一直等下章；主角轻易得到所有配合|
|第四章|新的阻力或对立方怎样基于自己的利益应对？主角原办法为何不再够用？|换名字和地点重复同一招；对立方无信息却全知|
|第五章|首轮事件是否形成结果与余波？人物关系是否变化？接下来还有什么持续动力？|五章没有完成一个小循环；靠旁白宣布成长；只留下空悬念|

这些是待回答的问题，按题材安排节奏，不强迫每本书套同一事件顺序或每章都有反派。每章约6000汉字要靠有效场景支撑，不靠解释、手续和重复情绪补字。保留有作用的生活细节、不同人物诉求、失败后的反应和改变下一行动的余波。

## 每次冻结前实读与验收

1. 前五章每次采用前，累计回读第一章至当前候选的实际全文与准确哈希。第三章复核短期事件链，第五章通读约三万字样稿。
2. 同一narrative_review.opening_five审阅八项：承诺兑现、主角选择、阻力自主应对、因果推进、人物与情绪、原创差异、语言与有效密度、下一章追读理由。结论必须有当前正文引文。
3. 写清上一章提出的问题本章回答了什么，以及本章结果如何形成新的具体压力。不能每章都用同一句“更大的阴谋出现了”充当变化。
4. 第三、第五章的sample_review逐章提供证据，审主线、首轮兑现、人物关系、长篇动力、对平台读者的适配性、可以一句话说清的卖点及剩余短板。
5. 所有影响追读、因果或平台适配的实质问题统一放在原reader.issues中，标must_fix或verify，未处理就不采用。只返修当前未冻结章，同章最多三轮，不清零次数、不另建评分角色。
6. 第五章只有内部审读完成才标internal_ready_for_submission，assessment_source固定为model_editorial_review。此状态只是内部样稿准备完成，不能登记为平台通过或已签约。

签约投递前仍需按选定平台核查当前材料要求、原创与AI辅助规则，准备标题、简介、类别、大纲与实际正文；核查缺口如实保留，不自动投稿，不拿“五章三万字”当作所有平台的固定要求。
