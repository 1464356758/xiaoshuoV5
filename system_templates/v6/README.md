# 小说主 V6.2.1

从零编写的小说工作核心：一条创作流程、一个Python命令行、一个正式状态。当前GPT负责写作和编辑，程序只负责记录与文件完整性。没有模型API、常驻服务、每日章数上限或自动签约承诺。

作者：将初始化包和新书仓库链接发到新的GPT工作聊天；选平台、选题、说开始。以后直接说“下一章”。不用自己执行命令。

每章6000汉字左右（5500—6500），默认150章；前五章整体设计并累计审读；每次请求一步完成本章写作、返修、冻结和远端回读。断点保存实际草稿，重试接续原目标。

正式使用前重新检查了空仓库首提交、草稿身份丢失、冻结中断重试、附件完整性与软件读取。冻结前再次核验实际材料，软件读取正文及记忆/计划/编辑快照；中文计数、原始UTF-8哈希与今天更新的判断保持一致。已有参考方法卡、人物场景检验和三层审稿继续按需使用。

本包只用于没有作品的新书仓库，原有README保留，不覆盖旧书。旧书仍用其原流程和冻结正文；工作台同时读取两种版本。新聊天上传初始化系统包.zip，提供新书仓库后，执行者负责实际部署；选平台、选题、确认开始后直接写作。网页用于管理、阅读和生成指令，需把指令发给本书GPT聊天才会写作。

执行者先读AGENTS.md、WORKFLOW.md，首次开书另读CRAFT.md。`python3 novel.py --help`查看命令；只有Python标准库，要求Python3.10+、Linux工作环境（操作系统文件锁）。作者的手机无需安装Python。

系统源码位于系统母版的system_templates/v6。research记录本次调研，validation保存独立试稿与实测；它们不是任何旧小说的正式新章节。软件端沿用管理清单、阅读和代发界面，V6核心不导入旧版的工作锁和审核工具。

仍然需要真实的编辑和市场反馈来判断开篇表现。自动验证、模型自审或参考书目录都不能证明签约。
